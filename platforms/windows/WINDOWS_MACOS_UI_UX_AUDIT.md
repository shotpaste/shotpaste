# Windows 对齐 macOS UI/UX 审查与改造台账

> 创建日期：2026-08-14
> 适用范围：仅 `platforms/windows/**` 以及 Windows 构建/测试门禁
> 工作原则：报告中的每个判断必须先以当前代码、运行行为和测试证据核实；错误或过时的判断不得机械实施。每项结论必须记录为“已改造”“现状已满足”“经核实不成立”或“明确的平台例外”，并附证据。

## 状态图例

- [ ] 待核实
- [x] 已闭环（具体结论见项目内的“最终状态”）
- `已改造`：报告属实，Windows 已完成改造并验证
- `现状已满足`：当前实现已经满足体验契约，不需要新增改动
- `经核实不成立`：报告与当前实现不符，记录反证后不修改
- `平台例外`：只能由明确的操作系统能力差异支撑，不以实现成本为理由

## 阶段 0：统一体验契约

每个入口均按以下状态表核验：

| 字段 | 必须回答的问题 |
|---|---|
| 前置状态 | 用户成果是否存在、是否 dirty、是否正在录制/合并/保存 |
| 用户动作 | 点击、键盘、窗口关闭、应用退出、系统事件分别是什么 |
| 视觉反馈 | 是否确认、是否非打断、是否可取消、焦点落在哪里 |
| 副作用 | 文件、剪贴板、数据库、临时资源、进程状态如何变化 |
| 失败恢复 | 磁盘满、无权限、路径失效、文件锁定等情况下如何重试或保留成果 |
| 最终状态 | 文件与历史记录是否一致，窗口/会话何时才可关闭 |

Windows 原生例外必须逐项写明；默认目标是功能、逻辑、UI、UE 和用户体验与 macOS 几乎一致。

## P0：必须最先处理的数据安全问题

### P0-01 未保存标注会直接丢失

- [x] 已闭环
- 报告判断：macOS 在标注有改动时，取消或 Esc 进入“保存 / 丢弃 / 返回”；Windows 取消按钮和 Esc 直接关闭窗口。
- 核验范围：所有截图/One Shot 标注入口、窗口关闭按钮、取消按钮、Esc、应用退出。
- 故障/行为验证：dirty 与 clean 两类会话；保存、丢弃、返回三条分支。
- 最终状态：`已改造`。原判断在改造前成立；clean 会话仍可直接退出，dirty 会话的取消按钮、Esc、窗口关闭、托盘退出统一进入“保存 / 不保存 / 取消”。
- 核验证据：`InlineAnnotateWindow.RequestCancelAsync/OnClosing` 在关闭前检查 `HasUnsavedAnnotations`；`AppController.ExitAsync` 必须等待 `RequestCloseForExitAsync` 的裁决完成后才可 `Shutdown`；对话框三按钮均有稳定 Automation ID。
- 改动与验证：真实 Inline E2E `dirty_return_discard`、`dirty_save`、`dirty_exit_return_discard`、`dirty_exit_save` 覆盖窗口内取消与应用退出，分别核对编辑器/进程是否仍在、PNG 数量及 SQLite 历史数量；保存分支确认文件落盘后才退出。

### P0-02 截图、长图保存失败后不保留成果供重试

- [x] 已闭环
- 报告判断：Windows 在真正写文件前关闭截图标注层；长图在 `finally` 关闭进度窗，失败后只剩错误提示。macOS 支持重试、换目录、复制当前图片；长图失败会保留合并结果并回到可完成状态。
- 核验范围：普通截图、One Shot、滚动截屏的保存状态机。
- 故障注入：无权限目录、无效/失效路径、目标文件锁定、模拟写入失败；验证成果仍可重试、换目录或复制。
- 最终状态：`已改造`。原判断成立；截图只有持久化成功后才结束标注会话，长图保存失败保留合并位图并停在可恢复状态。
- 核验证据：截图失败提供“重试 / 选择其他位置 / 返回”，返回后仍可复制；长图失败提供“重试 / 另存为 / 复制 / 丢弃”，进度窗具有 `SaveFailed` 状态。
- 改动与验证：`ImageFileService` 改为同目录临时文件、Flush、原子替换；锁定目标故障注入验证旧文件不变且临时文件清理。滚动 `SaveFailed` 阶段拦截 UIA/`WM_CLOSE`，把外部关闭映射为经确认的丢弃并保证恢复任务完成；真实 Scrolling HUD 测试验证外部关闭不会悬挂操作门，随后仍成功生成 1140×6858 长图。

### P0-03 录屏重录、删除、退出没有保护

- [x] 已闭环
- 报告判断：Windows 重录/删除会立即停止并以 `File.Delete` 永久删除；退出直接 `Shutdown()`。macOS 会确认重录/删除、移入废纸篓；录制中退出提供“停止并保存 / 丢弃并退出 / 取消”。
- 核验范围：录制中、暂停、录制完成预览、临时文件存在时的重录/删除/窗口关闭/托盘退出/系统退出。
- 故障/行为验证：确认分支、取消无副作用、Recycle Bin、删除失败、录制中退出三分支。
- 最终状态：`已改造`。原判断成立；重录、删除均先确认，废弃媒体移入 Windows 回收站；录制中退出提供“停止并保存 / 丢弃并退出 / 取消”。托盘退出和 Windows `SessionEnding` 共用同一异步退出协调器。
- 核验证据：`RequestRecordingRestart`、`RequestRecordingDiscard`、`ExitAsync` 均在改变录制状态前完成用户裁决并等待活动录制工作流；`App.OnSessionEnding` 在存在可恢复工作时先取消系统会话结束，再调用同一协调器，避免直接 Dispose 尚未封装的媒体。
- 改动与验证：统一接入 `RecoverableFileOperations`。Recording Lifecycle E2E 实际驱动重录取消/确认、删除取消/确认、退出取消→停止保存、退出丢弃，核对 MP4、SQLite 历史、回收站与进程退出；系统注销出于主机安全未真实执行，以 `OnSessionEnding` 接线契约 + 已实测的共享退出协调器验证。

### P0-04 Quick Access/历史单项删除永久删除且顺序不安全

- [x] 已闭环
- 报告判断：Quick Access 与历史卡片单项删除不确认；先删数据库记录，再永久删文件，失败被吞掉，可能产生孤儿文件。macOS 会确认、移入废纸篓，文件处理成功后才移除记录，并报告部分失败。
- 核验范围：Quick Access、历史卡片、批量删除、数据库存储服务及所有调用方。
- 故障注入：文件锁定、文件缺失、Recycle Bin 失败、数据库失败、混合成功/失败；验证记录与文件一致并报告部分失败。
- 最终状态：`已改造`。原判断成立；Quick Access、历史单项与批量删除均确认，只有自有文件回收成功且数据库事务提交后才从历史集合移除，失败可见且可重试。
- 核验证据：删除在同一数据库门内先执行未提交的 `DELETE` 作为写能力预检，再回收自有文件，最后提交事务并移除 UI；数据库锁定/只读时不触碰文件，回收失败则回滚并保留记录，文件缺失按已完成处理，外部剪贴板文件永不删除。
- 改动与验证：`CaptureHistoryDeletionSafetyTests` 覆盖数据库预检失败、回收失败、文件缺失、混合失败后重试及外部文件；真实 Inline Quick Access E2E 与 History E2E 分别验证取消保留、确认后文件进入回收站且数据库/卡片同步消失。

## P1：核心交互差距

### P1-01 选区放大镜与取色器

- [x] 已闭环
- 报告判断：macOS 在选区阶段显示像素网格、坐标、HEX/RGB，支持 Shift 切换和复制颜色；Windows 设置与 One Shot 没有对应状态。
- 体验契约：普通选区与 One Shot 均可见；边缘钳制、多显示器/DPI、Shift 状态、颜色复制和可访问名称完整。
- 最终状态：`已改造`。原判断成立。
- 核验证据：选区阶段现显示边缘钳制的像素网格、物理坐标与 HEX/RGB；Shift 切换格式，Ctrl+C 复制当前颜色，并有设置开关与可访问名称。
- 改动与验证：放大镜取样接入 One Shot 选择状态机；相关设置持久化，Inline 契约/真实选区 E2E 与 150% DPI 截图核验通过。

### P1-02 标注画布缩放与平移

- [x] 已闭环
- 报告判断：Windows 缺少手形工具、缩放预设、适应窗口、触控板缩放和 Space 平移。
- 体验契约：缩放中心稳定、预设/适应窗口、滚轮或触控板、Space 临时平移、手形工具、快捷键与焦点状态不冲突。
- 最终状态：`已改造`。原判断成立。
- 核验证据：工具条新增手形、适应窗口和缩放预设；滚轮、触控缩放、Space 临时平移共享变换，选区装饰与命中测试同步变换。
- 改动与验证：在现有 WPF/code-behind 编辑器内加入画布缩放/平移状态机，保留 One Shot 已提交选区不被 Space 拖动的契约；Inline 拖动与 4K 性能 E2E 通过。

### P1-03 标注参数跨会话持久化

- [x] 已闭环
- 报告判断：macOS 持久化主颜色、公共参数和逐工具参数；Windows 每次重用红色、20px 等硬编码默认值。
- 体验契约：颜色、线宽、字号及各工具参数独立持久化；无效旧值安全回退。
- 最终状态：`已改造`。原判断成立。
- 核验证据：`AppSettings` 现持久化主颜色、线宽、字号、圆角以及逐工具 `AnnotationToolSettings`；无效旧值由 `SettingsStore` 归一化。
- 改动与验证：工具参数变化立即写回设置，下一标注会话读取持久值；SettingsStore 与 AppControllerFlow 契约测试通过。

### P1-04 录屏临时标注模式

- [x] 已闭环
- 报告判断：macOS 支持临时修饰键和临时清除策略；Windows 没有实现，且存在要求字段不存在的反向契约测试。
- 体验契约：可配置临时修饰键、释放/超时等清除策略；迁移或替换反向契约测试。
- 最终状态：`已改造`。原判断成立，原“字段必须不存在”的反向契约已迁移为正向行为契约。
- 核验证据：可配置临时修饰键、临时清除模式、超时、淡出、最大数量及逐工具策略；临时策略只覆盖本次创建的标注。
- 改动与验证：`RecordingAnnotationState` 支持按工具过期/容量/淡出；对应 7 个状态测试与 `RecordingAnnotationTemporaryMode_IsConfigurableWithoutLegacySelectionServices` 通过。

### P1-05 录屏标注工具条形态

- [x] 已闭环
- 报告判断：macOS 为锚定在“笔”按钮旁的水平 Popover，随主录屏条原子移动；Windows 为可独立拖动、带标题和多行文字按钮的大面板，且缺少白色画笔。
- 体验契约：锚定、水平紧凑、随父工具条移动、不会独立漂移、包含白色画笔、键盘和屏幕阅读器可操作。
- 最终状态：`已改造`。原判断成立。
- 核验证据：大面板改为锚定录屏“笔”按钮旁的水平紧凑 Popover，取消独立拖动标题区；父录屏条移动时原子跟随，并新增白色画笔。
- 改动与验证：工具按钮补齐稳定 Automation ID/本地化 Name 与键盘操作；Popover 使用父录屏条所在显示器的物理工作区和 per-monitor DPI 定位，负坐标副屏与混合 DPI 布局测试、捕获排除及真实 Recording E2E 均通过。

### P1-06 Quick Access 键盘入口与导航

- [x] 已闭环
- 报告判断：Windows `ShowActivated=False`，没有 KeyDown 流程，托盘没有“聚焦 Quick Access”；macOS 支持菜单聚焦、Tab、方向键、Enter、Delete、复制和保存。
- 体验契约：显式聚焦入口；Tab/方向键/Enter/Delete/复制/保存；非聚焦展示仍不抢输入焦点。
- 最终状态：`已改造`。原判断成立。
- 核验证据：托盘新增“聚焦 Quick Access”；普通展示仍不激活，显式入口才进入键盘模式；支持 Tab、方向键、Enter、Delete，以及配置的复制/保存/打开等动作。
- 改动与验证：`QuickAccessWindow` 增加焦点进入/退出和完整 KeyDown 流程；Inline E2E 验证固定槽位、倒计时暂停/恢复及真实删除的取消/确认/回收站结果。150% 视觉门禁发现并修复悬停操作面板与重复角标按钮的真实重叠。

### P1-07 OCR 完成反馈过度打断

- [x] 已闭环
- 报告判断：Windows 打开并激活 520×390 中央置顶窗口；macOS 使用底部、非激活、10 秒自动消失、悬停暂停的链接卡片。
- 体验契约：默认非激活、靠近工作区底部、自动消失、悬停暂停、可复制/打开详情、屏幕阅读器可发现。
- 最终状态：`已改造`。原判断成立。
- 核验证据：改为工作区底部、默认非激活、非任务栏、10 秒自动关闭且悬停暂停的链接卡片；用户点击后可进入键盘操作，可复制全文、打开链接并由 LiveRegion 宣告，操作均有稳定 Automation ID/本地化 Name。
- 改动与验证：OCR E2E 验证中文、双二维码视觉顺序、链接顺序、剪贴板及空白图；人工截图发现并修复深色主题正文低对比度。新增工作区门禁还发现内容增高后的定位竞态，现于 `ContentRendered/SizeChanged` 重新按所在显示器定位，不再压住任务栏。

### P1-08 历史窗口生命周期

- [x] 已闭环
- 报告判断：Windows 为居中常驻普通大窗口；macOS 为失焦自动隐藏的临时浮动面板，并可切换“保持打开”，具有位置/尺度/默认筛选语义。
- 体验契约：浮动面板、失焦隐藏、保持打开切换、位置/尺度恢复、默认筛选与入口语义一致。
- 最终状态：`已改造`。原判断成立。
- 核验证据：历史改为浮动面板，默认失焦隐藏，可切换保持打开；持久化位置、尺寸、缩放与默认筛选，入口不再固定剪贴板类别。
- 改动与验证：History E2E 在 150% DPI 下验证默认截图筛选、1120×740 与坐标持久化、重启恢复、500 条虚拟化及全文查看。

### P1-09 无障碍：减少动画与高对比度

- [x] 已闭环
- 报告判断：Windows 有部分 Automation ID/Name，但动画不响应系统“减少动画”，高对比度适配不明确；录屏红点始终无限脉冲。
- 体验契约：系统减少动画/客户端区域动画设置关闭时停止非必要动画；高对比度使用系统可辨识颜色；屏幕阅读器语义与焦点顺序完整。
- 最终状态：`已改造`。原判断成立。
- 核验证据：`AccessibilityPreferences` 读取 `SystemParameters.ClientAreaAnimation` 与 `HighContrast`，高对比度改用系统画刷；录屏红点、点击涟漪、Quick Access、贴图、设置与通知均尊重减少动画。
- 改动与验证：无障碍契约测试覆盖系统信号与各动画入口；浅/深主题正文、次要正文及 OCR HUD 对比度均以 WCAG AA 4.5:1 门槛验证。滚动恢复 HUD 在失败状态转为可激活并聚焦“重试”，OCR LiveRegion、录屏主工具按钮及恢复操作补齐可读 UIA 语义。

## P2：次级但真实的体验差距

### P2-01 Quick Access 设置能力

- [x] 已闭环
- 报告判断：macOS 有实时卡片预览、启用/禁用、拖拽排序、槽位分配和重置；Windows 是六个匿名下拉框。
- 体验契约：可识别的实时预览、逐项启用、排序、槽位分配、重置、键盘替代操作和持久化。
- 最终状态：`已改造`。原判断成立。
- 核验证据：设置页具有实时卡片预览、总开关、六个具名槽位、拖拽/Alt+方向键排序、启用/禁用与重置；`None` 槽位保持位置而不挤压。
- 改动与验证：旧 `Save/Open` 配置迁移为 `SaveOrOpen`，槽位归一化保留索引；Inline Quick Access E2E 与 SettingsStore 测试通过。

### P2-02 历史设置与入口语义

- [x] 已闭环

- 体验契约：位置、默认筛选、缩放、存储占用、打开目录；不同入口只在明确需要时覆盖默认筛选。
- 最终状态：`已改造`。原判断成立。

### P2-03 设置架构

- [x] 已闭环

- 体验契约：核实当前两端信息架构；合并重复入口并保留深链接/Automation ID 稳定性。
