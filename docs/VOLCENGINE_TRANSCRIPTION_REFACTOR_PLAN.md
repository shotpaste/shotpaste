# 用户自有火山账户：录音文件转写改造方案

状态：macOS 文件识别、设置与持久化入口已接入；受限账户 HTTP PoC 与原生 App 公开样本真实链路均通过。Windows 暂缓。核对日期：2026-09-06。

本次实施范围按用户最新要求限定为 macOS；Windows 暂不实现，下文 Windows 项保留为后续计划。

## 1. 交付目标与选型

用户在 ShotPaste 内填写自己的云凭证，首次检查并初始化后即可使用录后转写。
云资源、录音、语音费用属于用户自己的火山账户；ShotPaste 不提供中转服务器，
不内置开发者密钥，不代理收费。录音本地保存成功后才进行云处理。

默认使用豆包录音文件识别模型 2.0，资源 ID 固定为 `volc.seedasr.auc`。
标准 HTTP 提交任务、轮询结果，替换当前 CLASI WebSocket 同传实现。
原始文字稿持久化后，可选地使用现有 Agent LLM 做润色、摘要和结构化整理。
原始转写结果不因 AI 整理失败而丢失或被覆盖。

不要求用户填写 Model ID、ASR URL、TOS Endpoint、桶名、目录或签名链接。
服务地址和资源 ID 由应用内供应商配置拥有，普通设置不开放任意上传地址。
实时字幕、实时翻译、译音播放不在本次改造范围内。

## 2. 凭证的真实边界

语音 API Key 可以调用语音服务，不能据此推导出 TOS 管理权限。
当前核对的标准文件识别要求 `audio.url`；极速版文档也要求 URL，且资源 ID
为 `volc.bigasr.auc_turbo`，不能承诺用 0.8 元/小时的 2.0 Key 直接上传 Base64。
因此，本地客户端、自有云账户、标准文件识别三项约束下，可靠方案需要两类凭证：

| 设置项 | 用户输入 | 用途 |
| --- | --- | --- |
| 豆包语音 API Key | 必填 | 仅调用文件识别 2.0 |
| TOS Access Key ID | 必填 | 用户的专用 IAM 子用户身份 |
| TOS Secret Access Key | 必填 | 对专用桶的请求签名 |
| 云区域 | 默认北京，高级选项 | 选择受支持的 TOS 区域；不是 ASR 模型地域配置 |

不把方舟文本模型 Key、语音 Key 和 IAM AK/SK 当作可互换凭证。
第一版不宣传“一个语音 API Key 即可完成全部云配置”。
若未来必须只有一个输入框，可支持用户导入含上述凭证的配置包，但仍是两套授权；
不把明文密钥放入普通配置导出。企业 STS 可作为扩展，须明确过期与刷新来源，
无刷新来源时不能承诺长期无人值守。

## 3. 首次设置与日常流程

### 首次设置

1. 设置 → AI 功能 → AI 转写：自动转写默认关闭。
2. 填写语音 Key、TOS AK/SK。密码输入框默认隐藏，粘贴完整值后显式保存，
   不随每个按键写入本地凭证存储，不以部分输入覆盖原凭证。
3. 点击“保存并测试”：依次保存本地凭证、配置私有临时存储、验证公开短音频；
   界面展示当前步骤。失败保留已完成的配置，测试成功后显示“可用”。
   也可仅点击“保存”，状态保持未测试；语法检查不等于云端验证。
4. 测试按钮旁说明转写及存储按用量计费，失败不自动循环提交收费任务。
   控制台链接放在高级选项，由用户完成条款、实名认证或计费开通。
   应用不能替用户静默接受云服务合同。
5. 默认创建本应用专用私有标准桶，并设置应用临时前缀的过期清理规则。
   已有私有存储可在高级选项配置。
6. 全链路通过后，在 One Shot 开始录屏前的弹窗选择“录屏完成后转写”、
   “转写后使用 AI 整理”和语音语言；开始时记住选项，取消不保存草稿。
   单独录音的对应选项仍在开始录音时选择。

“凭证已保存”“云端已验证”“自动转写已开启”是三个独立状态。
默认不改动 Agent LLM 设置，不开启自动上传，不把语音服务开通等同于采集授权。

### 日常使用

录音/录屏停止 → 本地音频保存完成 → 准备上传音频 → 上传至用户私有 TOS →
提交文件识别 → 查询结果 → 校验并保存原文与分句 → 清理云端音频 → 可选 AI 整理。

展示真实阶段和上传字节进度；服务处理期间显示“识别中”，不虚构百分比。
支持取消、重试、原文查看、带时间信息导出；原文与 AI 结果分开显示。
关闭结果窗口的行为与后台任务状态明确区分，不能靠窗口析构丢失任务。

## 4. TOS 初始化与最小权限

桶名由应用生成，例如 `shotpaste-tmp-<随机安装标识>-<debug或release>`，全局冲突时
重试随机后缀。验证桶用独立随机命名。桶名和资源引用存于非敏感配置，密钥单独保存。
桶内路径为 `transcription/v1/<installation>/<job>/<part>.m4a`，不用真实文件名、
标题、用户名、转写文本作路径。两个平台和多个安装实例只清理自己拥有的对象。

首次初始化权限与日常运行权限分开定义：

| 阶段 | 权限范围 |
| --- | --- |
| 初始化 | 创建指定专用桶、读取区域与桶属性、读取/设置该桶生命周期、检查私有访问状态 |
| 日常运行 | 专用前缀 PutObject/GetObject/DeleteObject；必要的 Head/List 与分片上传/中止权限 |
| 不需要 | IAM 用户/密钥管理、其他产品管理、全账户管理员权限、公共读写 ACL、删除桶 |

IAM Action 使用官方动作名；生命周期 IAM 名称为
`tos:PutLifecycleConfiguration`/`tos:GetLifecycleConfiguration`，与 SDK 方法名不同。
实施时交付资源限定的可复制策略，并用受限子用户验证；不能拿管理员成功替代最小权限验收。
应用不自动为自己增加 IAM 权限。权限不足时给出缺失动作和目标资源，保留已完成检查。

新建桶使用私有 ACL、标准存储，关闭版本保留相关选项，不启用 CDN、传输加速、归档、
访问时间跟踪或额外收费处理服务。沿用云服务默认的可靠性能力。
已有桶仅作为高级功能：需要明确选择并验证所有权、私有状态、版本控制、保留策略和清理权限；
不覆盖已有生命周期策略，不接管用户其他目录。默认方案不扫描或修改已有业务桶。

上传完成生成仅该对象 GET 的 HTTPS 签名 URL。URL 仅发送给语音识别服务，
不写日志、诊断、任务 JSON、剪贴板或普通配置；持久化对象引用，需要时重新签名。
签名有效期初始建议 24 小时，须结合实际排队和结果查询保留期限验证后锁定。
不能承诺 URL 到期就删除对象，也不能承诺 ASR 与 TOS 同厂商即免公网流量。

清理策略：

- 成功获取并持久化原文后，立即删除该任务上传对象，随后验证对象不存在。
- 取消或永久失败后安排删除；删除失败进入独立 cleanupPending 队列，文字稿仍可用。
- 专用临时前缀配置按最后修改时间的 2 天过期规则；该规则是兜底，不承诺整点/精确 48 小时执行。
- 应用每次启动及联网恢复时重试本安装的待清理对象；不阻塞录制和保存。
- 分片上传记录 upload ID，并在取消时中止；生命周期补充未完成分片过期清理。
- 不自动删除桶。用户卸载/移除凭证前，展示待清理数量及控制台手动清理入口。
- 云端过期删除只针对可重新生成的上传副本，本地原始录音仍按原历史契约管理。

## 5. 音频准备、识别和结果

macOS 使用已有 AVFoundation 音轨提取；Windows 使用现有原生媒体/NAudio 边界。
视频帧、截图、图片上下文、设备 MAC 地址不发送。优先复用本地 M4A，避免无意义 PCM 膨胀。
验证实际文件类型、非空、可解码时长、文件大小与音轨，不仅检查扩展名。

标准接口上限为 512 MB、5 小时。应用初始每份上限取 256 MiB、4 小时，
单任务最多一个在途 ASR 提交、全应用最多两个并发任务；可通过后续实测调整。
当前 macOS 的 10 分钟本地分块规则不能直接保留成云端提交规则：
短录音整体提交，超长录音按静音边界拆分，保存分块绝对时间偏移；
跨块说话人编号只在块内可信，不把相同数字当作同一个人的身份。
分块重叠若使用，必须做时间/文本去重并计入费用估算。

ASR API：

- POST `/api/v3/auc/bigmodel/submit`；`X-Api-Key`、`X-Api-Resource-Id: volc.seedasr.auc`、
  预先持久化 UUID `X-Api-Request-Id` 和固定序号；`request.model_name=bigmodel`。
  当前文档示例包含服务端 `task_id`，应单独保存并优先用于查询；本次实测成功响应
  未返回该字段，使用原 request ID 查询成功。缺少 task ID 时先查询原 ID，不能重新提交。
- `audio.url` 为临时签名链接，`format=m4a`；默认 `show_utterances=true`。
- 仅按对应版本文档发送语言、标点、数字规整、说话人分离参数。
  “自动”不能继续退化成强制中/英文；其他语言须按 2.0 实际支持表开放。
- POST `/api/v3/auc/bigmodel/query` 查询同一任务。同时验证 HTTP 状态与业务状态码，
  不把 HTTP 200、空文本或处理中当成功；校验终态、音频信息、分句类型及时间范围。
- 结果保存 text、utterances、起止时间、块内 speaker、来源轨道、模型版本、任务引用。
  保留“系统声/麦克风轨道”和“识别说话人”两种不同语义。

仅当录音方案已经选择独立轨道转写时分别上传轨道；否则上传既有混音，避免同一内容多次收费。
两条轨道各转写 1 小时通常按 2 小时音频预算，不能只按墙钟录制时长报成本。

## 6. 持久化、恢复与计费控制

保留现有 AudioProcessingTask/原始文字稿/AI 阶段边界，新增云任务子记录：

`jobID, partID, providerVersion, credentialProfileID, localAudioRef, sourceChecksum,
bucketRef, objectKey, uploadID, requestID, providerTaskID, submittedAt, status, pollAttempts,
retryAfter, resultRef, cleanupState, sanitizedErrorCode`。

禁止存储 API Key、AK/SK、Authorization、完整签名 URL 或云端错误原文。
云请求错误白名单映射成本地文案；诊断仅保留阶段、HTTP/业务错误码、耗时和可用 request/log ID。

状态顺序：`preparing → uploading → uploaded → submitting → submitted → polling →
persistingResult → transcriptReady`。`cleanupPending/cleaned` 是独立状态，
AI 后续仍使用 `polishing/organizing`。failed/cancelled 不删除本地原始数据。

- 发起提交前原子落盘 requestID；收到任务 ID 后立即持久化，再更新 UI。
- 上传成功但进程退出：从对象引用恢复，不重新上传同一份完好对象。
- 提交超时/连接断开：先查原 requestID，不盲目生成新 UUID。
  官方未保证幂等的情形下，不声称 exactly-once；查不到但受理不确定时提示用户决定重试，可能重复收费。
- 处理中按建议初始 5 秒、逐步退避到 30 秒并加抖动；遵守 Retry-After。
  具体 ASR 排队期限、结果保存期限在实施前从文档/实测锁定。
- 401/403、服务未开通、余额/额度不足不自动重试；429/暂时性网络问题有次数上限。
- 取消停止新请求并清理可删除副本；已被服务受理的识别未必能撤销或免单，UI 如实说明。
- 重试 AI 只读取已有原文，不再上传录音、不再提交 ASR。
- 切换凭证账户时不使用新凭证清理旧账户资源；保留旧清理引用，提供恢复/手动清理入口。
- 录制、历史保存、关闭应用的既有失败保留行为不依赖网络和 TOS 成功。

## 7. 安全与本地配置

macOS 与 LLM API Key 一样使用本地 UserDefaults，Windows 复用 DPAPI CurrentUser，各自通过集中构建身份隔离 Debug/Release。
增加 credential profile ID，支持显式替换/移除；保存失败保留上一组可用凭证。
校验空白、长度、控制字符，Web 页面复制出的分隔空格需提示并规范化，不能记录错误值。
普通导出只含非敏感选项和“需要重新填写凭证”的标记，不含明文凭证、DPAPI 密文或签名链接。

初始化和日常请求使用明确的官方 endpoint allow-list；禁止自动转发鉴权给重定向目的地。
签名实现使用平台可维护的官方兼容实现或经官方测试向量验证的签名模块，
macOS/Windows 不引入每次请求外起 Python/Node 的运行时。验证脚本仅用于研发，不进入产品。
添加依赖前检查许可和打包边界，按需更新 THIRD_PARTY_NOTICES.md。

## 8. 成本显示

按当前刊例：ASR 2.0 为 0.8 元/小时；北京标准单 AZ TOS 0.099 元/GiB/月，
公网流出 0.5 元/GB，标准请求 0.01 元/万次，普通上传免费。
应用显示“估算，不含优惠/重复请求/后续 AI，实际以火山账单为准”，价格表带核对日期，
不把估算当实时账单或账户余额。免费额度不假定已领取或有效。

示例：100 小时、每小时 30 MB、每对象保留 1 小时、公网完整读取一次：
ASR 80 元 + TOS 流量约 1.5 元 + 小于 0.01 元的临时容量/少量请求。
失败后的重新提交、双轨转写、分块重叠、ASR 多次读取都可能增加费用。
默认不买资源包、不充值、不启用加速/CDN；无用户支出授权不执行购买。

## 10. 实施顺序与验收门禁

1. 先完成用户账户 PoC：受限凭证 → 专用私有桶 → 上传 → 签名 URL → ASR 2.0 →
   原文/分句 → 删除 → 无鉴权不可读。确定实际时延、费用计量和请求权限。
2. 实现两个平台的 provider contract、TOS/ASR client 与脱敏；共享确定性协议 fixture。
3. 实现云任务持久化/恢复/独立清理，接入既有录音和录屏流程；停止复用同传协议。
4. 完成凭证设置、连接检查、资源初始化、费用提示、本地化和可访问性。
5. 回归取消、断网、超时、重复点击、应用退出重启、ASR 成功后清理失败、换账户、
   无效 Key、受限 IAM、超时签名、静音、多轨、长录音分块、AI 独立重试。
6. macOS 执行 `./scripts/run-tests.sh`、`./scripts/build_and_run.sh build --configuration Debug`，
   启动标准 Debug App 真机录音验收；本地化执行 CatalogTool verify。
7. Windows x64 执行 `scripts/build-windows.ps1 -Configuration Debug`，在已登录桌面运行
   `test-windows-parity.ps1 -Tier Interactive -SkipBuild -ProductExecutable <标准Debug产物>`；
   记录系统/DPI/设备，不能用 macOS PoC 代替 Windows 验收。
8. 最终 `git diff --check` 与改动范围检查，交付原生产物路径和未验证项；不自动提交/发布。

必须分开报告：HTTP 云接口 PoC、最小权限验收、原生应用链路、真实用户录音质量、
跨平台验收、自动清理实测。任一部分缺失不写成“只填凭证即可完整使用”已实现。
